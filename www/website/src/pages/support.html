What should your first support message contain?

A useful issue report makes the failure reproducible without granting anyone access to your private books.

  1. State the release version, installation method and affected route or command.
  2. Give the exact steps using a small fictional example and describe the expected and observed result.
  3. Include PHP and MySQL versions, the time of the failure and a sanitized error excerpt.
  4. Say whether the issue occurs on a fresh sample installation and whether a recent backup restore has passed.
php -v
mysql --version
php www/phpledger/install/preflight.php

Run these on your own installation. Review output before sharing it: a MySQL client version does not establish the connected server version, and private configuration is never useful in a public issue. The requirements guide explains the difference.

Frequently asked questions

These answers describe the current release and the choices you need to make before evaluating it.

What does support cost?

There is no published universal support price. Agree the task, availability, fees and completion criteria in writing before work starts.

Does this form send my message?

No. It prepares a local email draft or copies a message. You choose whether to send it through your own email application.

Is a response time guaranteed?

No public response-time guarantee is stated. Availability and response expectations are agreed individually.

Can support certify my accounts or tax return?

Software installation and workflow support do not replace qualified accounting or tax review. Statutory reporting and regional adapters remain separate product gates.

Where should I report a security problem?

Follow SECURITY.md in the project repository and contact the maintainer privately. Do not post credentials, exploit details involving customer data or private records in a public issue.
