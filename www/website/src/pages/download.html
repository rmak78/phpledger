Install from the browser

Six steps from upload to sign-in, with no terminal on your side. The installer explains each check it makes and stops with a clear message if the host is missing something.

  1. Upload and unpack

    Upload the ZIP to your host and unpack it where your site lives, with the document root pointing at the public folder.

  2. Open /install

    Enter the private setup key from the package to start the installer. The key stops anyone else from installing over your files.

  3. Host and database checks

    The installer checks the PHP version, extensions and database server before anything is written.

  4. Connect and migrate

    Enter the database connection. The installer runs the migrations and records the schema version it installed.

  5. First account and business

    Create the first account and set up your business: name, base currency, country package and financial year.

  6. Sign in

    Sign in and start with your chart of accounts, tax codes and opening balances, or open a sample company to practise first.

Updates and recovery

Updates arrive as signed releases, applied from /maintenance.php. Before every update the application takes an automatic backup that matches the release, so the books on disk and the schema being upgraded always agree, and the signature is verified before a single file is unpacked.

If a migration fails part-way, recovery runs automatically and the application returns to the previous working release. Hosts that need it can also use a CLI companion for recovery outside the browser.

Upgrading from a preview

Preview builds do not follow the one-step update path. The upgrade from a preview release is staged manually, and UPGRADE.md inside the ZIP describes each stage in order, with the checks to run between them.

Read UPGRADE.md before you start and take a backup first; the staged path is deliberate, because preview databases can differ from the {{site.release.version}} schema in more than one place.

Questions before you install

Can I use it for real books today?

Yes, with the published limits in mind. Version 1.0.0 is the first stable release, and the accounting core covers invoices, bills, stock, bank reconciliation and the standard reports. Independent accounting and security reviews, and supervised pilots, are still open commitments on the roadmap. Keep backups, and read the roadmap before you commit a live business to it.

How do I verify the download?

Each release page publishes a .sha256 file next to the ZIP. Compute the SHA-256 checksum of the ZIP you downloaded and compare it with the file before you unpack anything. If the checksums differ, do not install it; download the package again.

Does shared hosting work?

Yes. PHP Ledger is built for ordinary shared hosting: PHP 8.2 or later with the required extensions, a MySQL 8.4 database, and HTTPS. Installation runs in the browser, with no terminal, Composer, Node or Docker needed for setup.

What about MariaDB?

MariaDB is not validated for version 1.0.0. The application targets MySQL 8.4 with InnoDB and the utf8mb4_0900_ai_ci collation, and the release tests are run against that. If your host offers MySQL 8.4, use it.

Which licence applies?

New project-owned code uses AGPL-3.0-or-later; a commercial licence is available on request. Dependencies, fonts, photographs and the archived 2015 application keep their own terms.

Where is the source?

The full source is on GitHub at github.com/phpledger/phpledger. The release tag v1.0.0 holds the package, the checksum file and the release notes, and the repository carries the development history.

Automated test suites, fault-injection tests of the update and recovery path, exact-artifact installation, upgrade and recovery checks all passed. Independent accounting review, independent security review, supervised pilots with a real month-end close and a release-candidate period have not been performed yet; they are open post-release commitments listed on the roadmap.
