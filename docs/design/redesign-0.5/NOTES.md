## Resolved in QA pass

- [setup] `[data-slot="strips"]` is now wired generically in proto.js: any element carrying `data-shell-strip` is moved into the shell's real strip slot at render time. Removed the duplicate `screen:rendered` relocation listener from `src/ext/setup.js` (now just its header comment). `readiness-strip` and `demo-transactions` are unaffected — same visual result, one less code path.
- [daily] `.split-view-list { min-width: 0; }` is now generic in `src/app.css`, so any wide table inside a split-view list pane (not just journals-list's 6-column one) can shrink below its content-based automatic minimum instead of pushing the detail pane off-viewport. Removed the screen-scoped override from `src/ext/daily.css`.
- [setup] `.alert a { text-decoration: underline; text-underline-offset: 2px; }` now lives in `src/app.css` next to `.alert p`, matching what the surrounding comments already described. Removed the duplicate from `src/ext/setup.css`.
- [setup] `.panel-actions-note` now always takes its own full row (`flex: 1 1 100%`) instead of shrinking to a sliver and wrapping character-by-character next to action buttons at narrower widths. This replaces the per-screen `basis-full` workaround, which has been removed from `readiness-strip.html` — same layout, generic now.
- [sales] `.doc-lines-table` no longer hardcodes an absolute `min-width` (previously 66.875rem, sized only for the 8-column invoice/bill layout). Column widths are now percentages on every `<th>` (see COMPONENTS.md), which — combined with `table-layout: fixed` and tighter cell/input padding — scale proportionally to whatever width the table actually has, so Amount and the delete button are never pushed behind an invisible scrollbar at 1024×768. Fixed in `ar-invoice-new.html`, `ap-bill-new.html`, `ar-credit-note.html`, `purchase-order-new.html`, `journal-new.html`, `journal-unbalanced.html`. `goods-receipt.html`'s separate `.gr-lines-table` class (6 columns, no oversized min-width) was already a valid, independent fix and was left as-is. Added a narrow-viewport (<1024px) fallback `min-width: 46rem` on `.doc-lines-table` so very narrow views (768px) get a horizontal scroll instead of clipped digits, without touching the now-validated 1024/1366 behavior.
- [sales] Screen-id mismatch between shell.html's sidebar hrefs and screen ids (ar-list, ap-list, parties-list, purchase-orders-list, products-list, tax-codes) — re-checked with a full href/data-href/crumb link audit against every screen id; no broken targets remain anywhere in the prototype (only `components.html` and `sample-guide.html` intentionally have empty `nav`).
- Sidebar: active nav item now scrolls into view on render, and a `.nav-group-collapsible` (Setup) auto-expands when one of its own items is the active one — both generic, in `proto.js`.
- Logo: `src/phpledger-horizontal.png` background is now transparent (soft alpha ramp, clean anti-aliased edges) — verified on `login`, `login-error`, `companies`, and the OAuth screens.
