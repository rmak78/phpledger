# PHP Ledger 0.5.0-preview — local P0–P2 release board

Status date: 2026-09-16 (Asia/Karachi)

This is a local working record for the 0.5.0-preview candidate. It is not a
publication receipt, accessibility declaration, hosted capacity result, or
production-readiness claim.

## Decision in one sentence

The candidate can continue local implementation, but it must not be published
until the sample-import contract is made operationally truthful, Docker-backed
accounting tests run on a healthy isolated database, and the selected
application redesign is implemented and observed across active routes.

### Pakistan fiscal-year research

The setup copy treats entity type as guidance, not as a legal or tax engine.
The [FBR Income Tax Basics](https://www.fbr.gov.pk/income-tax/51147/61148)
material describes the normal tax-year concept and special-year examples. The
[FBR due-date material](https://www.fbr.gov.pk/categ/income-tax-due-dates/51147/40846/81148)
shows that filing dates differ by taxpayer category. The UI therefore presents
30 June as the normal Pakistan tax-year end, offers common calendar
and quarter-end choices, and tells the user to confirm a special year with an
adviser. It does not claim that an entity dropdown determines eligibility.

The supplied YouTube playlist was read through its public feed because the
playlist page itself was not crawlable. Its setup sequence covers business
profile, branches/regions, stores, equity/drawing/liquid/consumption/internal
issue accounts, sale agents, taxes, item categories/items, customers and
suppliers. This supports a more staged setup and workspace model; it is vendor
workflow research, not an accounting or compliance endorsement.

The matrix-backed vertical account follow-up is recorded in
`docs/research/0.5.0-VERTICAL-COA-RESEARCH.md`. The new
`resources/coa/industry-profiles-0.5.0.json` file maps all eleven selected
samples to a bounded account vocabulary, seed role labels, control
distinctions, unsupported operations, and source URLs. It is embedded into
sample evidence and used only to improve isolated sample account labels; it is
not a national chart, tax package, or real-company installer input.

### UX and competitor research

Fresh local captures confirm that the existing onboarding is a long mixed form
with raw `MM-DD` fiscal-year input and a large chart preview, while the older
transaction capture has a crowded horizontal navigation bar. Three independent
candidate visual directions were generated from those screenshots:

1. **Ledger Desk** — persistent rail, Today dashboard, quick actions and a
   review-oriented work surface.
2. **Today First** — command search, “record today’s work” composer, activity
   stream and contextual detail drawer.
3. **Books & Workspaces** — accounting workspaces grouped in a persistent rail
   with setup choices presented as a focused panel.

Product-design ideation requires a product-owner selection before a complete
visual build. These are candidates, not implemented or approved screens.

The patterns were compared with official product documentation for
[Frappe workspaces](https://docs.frappe.io/erpnext/workspace),
[ERPNext accounting](https://docs.frappe.io/erpnext/accounts),
[Odoo accounting onboarding](https://www.odoo.com/documentation/17.0/applications/finance/accounting/get_started.html),
[Odoo dashboards](https://www.odoo.com/documentation/18.0/applications/productivity/dashboards.html),
and [Salesforce navigation](https://help.salesforce.com/s/articleView?id=platform.customize_lex_nav_menus_create.htm&language=en_US&type=5).
[HysabOne](https://hysabone.com/) was used as Pakistan-market workflow
inspiration only; its product claims are not treated as independent proof.

## Implemented in this local candidate

- shared version helper renders `0.5.0-preview` as a logo overlay and footer
  identity;
- crowded company navigation is grouped into Work, Review and Manage menus
  while retaining server-side module visibility checks;
- local authenticated sample chooser resolves only the bundled, checksummed
  catalogue and provisions one isolated selected company;
- setup copy now has entity-type guidance, named fiscal-year choices, custom
  date validation, preserved values and a cautious Pakistan-year-end note;
- the eleven-pack builder was restored and now pins scenario metadata and any
  authored sample material as research evidence;
- supported operational contract events now replay through the existing
  AR/AP, Purchasing, Inventory and general-journal services during isolated
  provisioning; unsupported vertical operations remain explicitly staged in
  the installation receipt;
- chart snapshots and sample receipts are separated into append-only,
  trigger-protected installation history so sample metadata cannot overwrite the
  original chart snapshot;
- local shell and sample-pack tests were added/extended without adding a second
  posting path or database layer.
