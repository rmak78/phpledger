## Decisions to apply

1. **Target segment.** Sales-tax-registered SMEs, sole traders, AOPs and Pvt Ltd companies in Pakistan first. The buyer is often the accountant, tax consultant or software house operating books for several clients; the owner at the counter is phone-first. The informal kiryana tier is not a target. Real-time owner's equity — and for AOPs, partners' capital accounts with profit-sharing ratios and drawings — is the headline reporting feature.
2. **Licence: AGPL-3.0 for the core from now on. The accounting core is and remains open source.** Published 0.1.x previews stay MIT and are not relicensed. **Dual licensing:** the project offers a commercial licence for parties who want to use the core without AGPL obligations (embedding in a closed product, or hosting a modified version without publishing changes); the CLA must grant rights sufficient for that. Commercial modules will be declared explicitly, later; none is declared now. Candidate (not committed) commercial modules: native desktop and Android clients, an informal "khata" unposted sub-ledger add-on, a hosted FBR relay, a multi-company consultant edition. The core and every currently published module (including the POS showcase) are and remain AGPL. Self-hosting for one's own business is always free; the software must never require a licence key or contact a licensing server.
3. **CLA now.** Adopt a contributor licence agreement using CLA Assistant (GitHub Action `contributor-assistant/github-action`). Contributor PR #65 has already been reverted (`a157e52`) and replaced with owner-authored code (`916aebb`).
4. **Scope.** Park the "installer builds the customer's website" idea. Native desktop and Android clients are **not** parked: they consume the API/MCP layer and are planned paid add-ons. POS and an e-commerce/storefront module are the expected commercial drivers and move ahead of restaurant and distribution. Restaurant, distribution and specialist verticals stay as later modules.
5. **Sequence.** API/MCP reads (in flight, `1541e27`) complete first → AR → AP → Pakistan tax adapter with FBR digital-invoicing client → purchasing/inventory → shop POS → e-commerce/storefront → controlled API/MCP commands → restaurant → distribution → specialist. Distribution packaging (Softaculous, Installatron, Docker Hub image, Packagist) and an in-app updater become a named milestone immediately after AP.
6. **PHP floor 8.2.** Audit for syntax and functions that require 8.3, 8.4 or 8.5 and replace or polyfill them; update `composer.json` `php` constraint, README, `resources/release/INSTALL.md`, Dockerfile, CI matrix and any readiness check that tests the PHP version.
7. **Languages and offline.** Urdu first, then Arabic; RTL support; English remains the fallback catalog. Offline means **queued entry only — never offline posting**: browser clients queue entries in browser storage and submit when online; future desktop/Android clients use periodic sync over low-bandwidth connections. Posting, period control and reversal always execute on the server.
8. **FBR.** Ship an open-source FBR digital-invoicing client against PRAL's DI API (sandbox scenario runner SN001–SN028, token storage, HS/UoM reference sync, QR/logo on printed invoices, 72-hour edit window, debit/credit notes, and Annex-A/C/I built from the ledger plus DI responses). No licence is needed to ship the client; PRAL is a free integrator of record. Bixisoft's own licensed-integrator application is a future company decision, not a product dependency.
9. **Regional order after Pakistan.** UAE, Saudi Arabia, Oman; then Singapore, Malaysia, Sri Lanka, Bangladesh. The tax adapter contract must accommodate FBR (JSON/REST), ZATCA (XML/UBL with cryptographic stamping), UAE Peppol PINT and Oman before AR/AP schemas are finalised.
